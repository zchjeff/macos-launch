# 控制台提供纯计算工具箱，不碰展示层与任何应用文件

控制台在「分组管理」之外新增一栏「工具」，首批收录 JSON 格式化、二维码生成等日常运营与开发用的小工具。

工具与「应用 / 分组」完全无关，只做**纯计算**：

- **不读写**任何应用包或应用相关文件；
- **不写入**配置（不新增 `AppBoxConfig` 字段、不抬 `schemaVersion`、不参与方案导入导出与备份）；
- **不读写**控制台当前选中的分组 / 应用。

唯一会写磁盘的动作是用户显式点击「导出 PNG」，由用户指定路径。

## 理由

ADR-0004 把控制台的职责限定为「只管理展示层」，理由是 AppBox 的定位是「整理与启动」，不是软件管理器，不碰磁盘上的应用文件能让权限需求保持在最小集合。

工具箱与那条定位的关系需要说清楚：它既不是「展示层」，也不是「软件管理」，而是**第三种东西——没有副作用的计算**。把它放进控制台，是因为它和分组管理一样属于「用户主动打开控制台才会用的低频操作」，另开窗口或热键只会增加界面数量而不增加价值。

只要守住「纯计算」这条线，ADR-0004 的最小权限结论依然成立：工具不写配置文件，就不会出现「随手改个设置把新字段抹掉」；不碰应用文件，就不需要任何额外权限。

## 后果

- 工具的输入与参数**留在内存**：切工具、关控制台窗口都不丢，退出进程才忘。为此工具状态有一个独立于 `ConsoleModel` 的 `ToolboxModel`，挂在窗口控制器上——控制台窗口关闭只是 `orderOut`，控制器还活着。
- 工具不参与方案备份，这是有意的：备份描述的是「应用被组织成了什么样」，工具状态不是这个集合的一部分。
- 正则等**可能指数级回溯**的计算必须带预算（输入长度上限 + 墙钟超时）。「取消」的语义是**放弃等待，不是中断**——`NSRegularExpression` 一旦进入指数级回溯就在 C 层阻塞，无法从外部打断。能保住的底线是「界面不冻结」，不是「CPU 不浪费」。
- 一旦某个工具需要写配置文件或应用文件（例如批量改文件的替换），它就跨过了本条边界，必须重新立项而不是顺手加进去。
