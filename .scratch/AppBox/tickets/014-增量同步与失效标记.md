# FSEvents 增量同步与失效标记

**Blocked by**: 005, 011

## 目标

新装的应用下次唤起覆盖层就能在「未分类」里看到；被删除的应用在控制台里标记为「失效」，覆盖层里不再出现。不需要重启 AppBox。

## 涉及层

- [ ] 数据层：配置中记录每个应用的 `lastKnownPath` 与 `isMissing` 状态
- [ ] 逻辑层：`Watching` 端口 + FSEvents 实现；目录变更后触发重扫描；与配置合并时判定失效
- [ ] UI层：失效状态在控制台中的呈现（已在 011 完成）+ 变更后覆盖层快照刷新
- [ ] 测试：用假 `Watching` 手动触发变更事件，断言快照与失效标记的变化

## 验收标准

- 监听 `/Applications`、`/System/Applications`、`~/Applications` 的目录变化
- 新装一个应用到 `/Applications` 后，下次唤起覆盖层即能在「未分类」中看到它，无需重启 AppBox
- 删除一个已分组的应用后，控制台出现「失效」条目，覆盖层不再显示它
- 应用被**移动位置**（如 `/Applications` → `~/Applications`）后，不被标记失效，配置完整保留，仍能正常启动
- 外接卷未挂载导致应用暂时不可见时，标记为失效而非删除配置（配置永不静默丢失）
- `lastKnownPath` 在每次成功扫描后刷新
- 目录变更后快照刷新不应造成覆盖层可见的闪烁（若覆盖层正处于打开状态）
- 连续快速变更（如一次性拖入 20 个应用）不造成重复扫描风暴（需要合并/节流）
- 单元测试：假 `Watching` 触发"新增"、"删除"、"移动"三类事件，断言快照与失效标记

## 备注

- 判定"移动"而非"删除+新增"的依据是 bundleID 相同、路径不同（ADR-0003）
- FSEvents 的节流窗口需要明确设定并写入代码注释说明理由
- 应用扫描本身在 003 已完成，本切片只加"增量触发"与"失效判定"
