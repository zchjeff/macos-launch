# 覆盖层键盘导航

**Blocked by**: 007

**状态**：已完成（2026-09-27）

## 目标

不用鼠标也能操作覆盖层：方向键在图标间移动高亮，Enter 启动高亮项，Esc 退出或返回，输入字母直接跳到对应应用。

## 涉及层

- [x] 数据层：无（`LibrarySnapshot.tiles(at:)` 是新增的纯投影，属于逻辑层）
- [x] 逻辑层：`GridNavigation`（移动与字母跳转的纯函数）、`OverlayModel` 的 `selection / topSelection / move / jump / activation / reconcile`
- [x] UI层：`OverlayView` 高亮焦点环、换行自动滚动；`OverlayController` 键盘监听升级为全键位
- [x] 测试：`OverlayKeyboardTests`（3 个 suite、17 个测试），216 → 233 个测试、33 → 36 个 suite

## 验收标准

- [x] 覆盖层唤起后，高亮默认落在第一个图标上
- [x] 方向键按网格几何关系移动高亮：左右在同行内移动，上下跨行移动
- [x] 高亮移到网格边缘时行为明确（不越界崩溃；是否环绕由实现决定并在代码注释中说明理由）
- [x] 高亮项超出可视区域时，网格自动滚动使其可见

- [x] 在子网格中按 Esc 返回顶层；在顶层按 Esc 收起覆盖层
- [x] 在顶层直接输入字母/数字，高亮跳到**名称以该字符开头**的第一个应用
- [x] 单元测试：网格列数从 1 到 12 变化时，上下左右移动的结果都正确

## 移动规则：到边停住，不回绕

`GridNavigation.destination` 是纯函数，把「从第几个格子往哪个方向挪一格」算成另一个下标：

- 左右在**同一行内** ±1，到行首/行尾停住；
- 上下跨一行 ±columns，到首行/末行停住；
- 末行不满不丢项：最后一行第 k 个从上一行第 k 列按下来能到；
- 越界的下标先夹回 `0..<count` 再算——快照刚变小时可能来不及夹，调用方不用自己保证范围。

到边停住而不是回绕：回绕会让「按一下左」跳到上一行的末尾，位移不可预期；停住则每次按键最多挪一格（或一行），手感和眼睛都好跟。这条理由写在 `GridNavigation` 的文档注释里。

测试是几何性质的，不是抄一遍实现：`directionStaysOnItsAxis` 对 1–12 项逐项验证「左右不换行、上下不换列且只差一行」；`everyTileIsReachable` 用 BFS 从 0 号出发，验证 2/5/9/22/60/100 个格子时每个格子都走得到（不存在被隔断的孤岛）；`neverEscapesBounds` 对 1–3 项 × 1–12 列 × 全部下标穷举，结果必须在 `0..<count` 内。

## 同一份投影喂给视图与键盘

`LibrarySnapshot.tiles(at: level)` 是「当前这一层摆着什么」的唯一出处：视图拿它画格子，控制器拿它算键盘移动（`currentTiles()`）。画出来的和键盘走的必须是同一份，否则高亮会落到一个看不见的项上——分层开两个投影，迟早对不上。

## 高亮状态也放进 `OverlayModel`

`selection` 和 `topSelection` 放在模型里而不是视图的 `@State`：视图树在快照变化时会被整体重建（`rootView` 重赋），`@State` 会跟着丢。模型还有两条规则被单测钉住：

- 进子网格时把顶层高亮记下来（`topSelection`），返回时放回去——否则展开一个方块再回来，高亮会跑到第一个应用上，紧接着按回车启动的就是另一个东西了；
- 快照变化时把两个下标都夹回各自的格子数（`reconcile`）——分组被删、应用被隐藏之后，高亮不能停在一个不存在的位置上。

空层（空分组的子网格）没有格子：不画高亮，回车也什么都不会发生（`activation` 返回 nil）。

## 首字母跳转：一键一个确定的位置

`firstIndex(matching:)` 只找**第一个**匹配项，大小写不敏感；重复按同一个字母不会往下轮——「轮着找」是搜索框（009）的活。匹配是 `lowercased().hasPrefix`，即中文名要输入中文首字（拼音首字母属于 009 的搜索匹配，这里不做）。

修饰键的分工：方向键自身带 `.function` 标记，所以修饰键这一关只卡字母这一路；带 ⌘/⌃/⌥ 的组合键原样放行给系统和菜单（⌘Q 之类）。没被消费的按键返回 `event` 而不是 `nil`——消费掉的方向键不再往响应链上走，是因为 `ScrollView` 自己也会响应方向键，不拦下来就会「高亮挪一格、网格又自己滚一段」。

## 换行才滚动

高亮的滚动用 `ScrollViewReader` 的 `scrollTo(anchor: .center)`，但只在**换行**时触发（`onChange` 里比较 `old / columns != new / columns`）：左右挪动不换行，视图就不动；换行时视角跟着走一格，高亮始终停在中间附近，像编辑器的光标。子网格开着的时候顶层网格不响应——那会儿高亮走的是子网格那一份。

## 焦点环套在方块外面

白色描边在浅色材质上是看不见的（真机上验证过：只剩图标表面亮一点）。换成系统风格的焦点环：`Color.accentColor` 3pt、106×106、圆角 22，比 96×96 的方块大一圈留出缝隙。真机截图里一眼可辨。

## 回车与点击走同两条路

`activateSelection` 只看 `OverlayActivation` 的类型：单图标 → `activate(entry)`（启动 + 收起），方块 → `model.open`（展开子网格）——和鼠标点击走的是同两条路，不在键盘分支里复制一遍启动语义。

**代码侧**：233 个测试通过（36 个 suite）。本切片新增 17 个：移动几何（手算锚点、逐项不变式、BFS 可达、边界穷举、空网格、越界夹取）+ 字母跳转（大小写、无匹配不动）+ 高亮状态（默认落位、几何移动、顶层记忆、reset 忘掉两级、快照缩小后夹取、空组无处可去、activation 判型、跳转）。

**真机侧**（临时 3 组配置：工具 = Terminal + Calculator、开发工具 = Console + Script Editor，其余应用全在顶层）：

- 唤起后高亮落在第一个图标上，蓝焦点环清晰（`/tmp/kb-h-initial.png`、`/tmp/kb-h-zoom.png`）
- 方向键：`right,right` 同行 +1、`down` 跨行 +7，焦点环跟着走（`/tmp/kb-b-1-zoom-big.png`；首轮 `right,right,down` 从中位落到 Automator，`/tmp/kb-c-jump-f.png`）
- 自动滚动：12 次 `down` 后高亮夹在最后一格（开发工具），网格滚到底、高亮可见（`/tmp/kb-d-scroll-bottom.png`）——对照压力：顶层 60+ 个格子、约 9 行，远超可视的 7 行
- 字母跳转：`char:F` → FaceTime（展示顺序里第一个 F 开头的应用）；`char:工` → 工具方块（`/tmp/kb-e-jump-gong.png`）
- `return` 在方块上 → 展开「工具」子网格，标题 + Calculator（高亮）/Terminal（`/tmp/kb-f-subgrid.png`）
- `escape` 在子网格 → 回顶层，高亮复原到工具方块、滚动位置保持（`/tmp/kb-g-back-top.png`）

- `char:F,return` → FaceTime 被启动（进程起来了）+ 覆盖层收起，回车在单图标上等价点击
- 全程 `default.json` 的 sha 不变（`fd1fc496…` 前后一致）；核对完把临时配置还原成用户的原件（sha `31d782c2…`），启动的 FaceTime 已退出

**工具限制**：⌥+Space、Esc、方向键这些按键的外部合成全被自动模式拦截（连坐标点击也拦）。核对改用**进程内 NSEvent 合成**：让应用自己往事件队列里塞真实的 `NSEvent`，键盘监听按正常路径收到——这样验的是真实监听链路，只是触发者换了个。这套 TEMP 代码（`debugWatchKeyFile` / `debugSendKeys` / `debugPost` 与三个环境变量钩子）核对完已删除并重建 bundle；`grep` 过全仓库无残留。

**真机核对的意外发现**：两次运行的顶层排序看起来不同（一次从「Apps」开头、一次从「妙手」开头），一度怀疑排序不稳定。用 `localizedStandardCompare` 直接对照后确认不是——zh_CN 下它把中文名排在拉丁名之前（工具 < 开发工具 < 妙手 < 智谱清言 < Activity Monitor），两次运行的开头差异其实是一次自动滚动把第一行滚出了视口。排序是确定的全序，无需改动。
