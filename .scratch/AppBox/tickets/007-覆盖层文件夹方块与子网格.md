# 覆盖层文件夹方块 + 展开子网格

**Blocked by**: 004, 006

**状态**：已完成（2026-09-27）

## 目标

覆盖层顶层显示分组文件夹方块（内含组内前 9 个应用的缩略图标），点击方块全屏展开为该组的应用子网格，点空白处或 Esc 返回顶层。

## 涉及层

- [x] 数据层：`LibrarySnapshot.topLevelTiles`（分组 → 方块 / 单图标的投影）、`OverlayTile`、`FolderTile`（缩略图标取前 9 个）
- [x] 逻辑层：`OverlayModel`（顶层/子网格导航 + `reconcile`），控制器持有它并接线 Esc
- [x] UI层：`OverlayView` 重写（顶层网格一直挂着 + 子网格覆盖层、展开动画、空态）、`FolderTileView` 缩略图标排布
- [x] 测试：`OverlayTileTests`（14 个），202 → 216 个测试、31 → 33 个 suite

## 验收标准

- [x] 顶层平铺显示：所有分组作为文件夹方块，加上未分组应用的单图标，位于同一网格
- [x] 文件夹方块内显示组内**前 9 个**应用的缩略图标
- [x] 组内应用不足 9 个时，方块内不留空白占位，图标按实际数量排布
- [x] 组内应用超过 9 个时，只取前 9 个，不显示"+N"之类的角标（保持方块视觉干净）
- [x] 点击方块全屏展开为该组应用的子网格
- [x] 点击空白处返回顶层
- [x] 按 Esc 返回顶层（**不是**直接收起覆盖层——Esc 在子网格里先返回顶层，在顶层才收起）
- [x] 从子网格返回顶层后，之前的滚动位置与高亮状态被保留
- [x] 隐藏的应用不出现在方块缩略图里，也不出现在子网格里
- [x] 空分组仍显示为方块，展开后显示空态提示
- [x] 分组或应用数量超出单屏网格容量时，网格可纵向滚动，不丢失任何条目
- [x] 单元测试：缩略图标选取在 0 / 1 / 8 / 9 / 10 / 50 个应用时都正确

## 顶层网格一直挂着

顶层网格与子网格不是二选一，而是 ZStack 里叠着的两层：`topGrid` 无条件在，子网格按 `model.level` 盖上去。这不是为了少写代码——返回顶层时滚动位置与悬停高亮**不用另存再恢复**，因为承载它们的视图从头到尾没被卸载过。真机上可以验证：子网格打开期间，辅助功能树里两个滚动区同时存在，顶层那个的滚动条读数纹丝不动。

代价是子网格得自己带一层不透明背景——它盖住的顶层网格不能被看见。

## 导航状态放在控制器里

`model.level` 不能是视图的 `@State`，两个原因：

- 视图树在快照变化时会被整体替换（`rootView` 重赋），`@State` 会随之丢失；
- Esc 的判定在视图之外——`NSEvent` 本地监听器判完键码才决定是「回顶层」还是「收起」。

所以 `OverlayModel` 放在 Core 层（无 AppKit 依赖），`open / back / reset / reconcile` 四个动作全部单测覆盖。视图只读 `level` 决定盖不盖子网格；Esc 监听器与空白点击共享同一个 `back()` 返回值——`back()==false` 表示已在顶层，才轮到收起覆盖层。

## 「快照变化不跳位」是靠结构保的

`apply()` 只在快照真的变了时替换 `rootView`。替换会重建视图树，但顶层 `ScrollView` 在树里的结构位置没变，SwiftUI 保留它的滚动偏移。真机上专门构造了这份压力（探针应用把内容撑到 9 行、滚到底部、再丢一个应用触发重建）：重建前后顶层滚动条都读 1，网格没有跳回顶部。

滚动条读数可信是因为它跟着偏移走：对着它 `setValue 0 / 1` 能让网格在顶部/底部之间来回走。

新增与删除的应用都当场反映到网格上（同一个重建通道），且全程 `default.json` 一个字节没动——扫描与同步只读配置。

## reconcile：控制台删掉的分组

快照变化时如果当前打开的分组没了（在控制台里被删掉），`reconcile` 让那层子网格自己退掉，而不是留在一个不存在的组上。分组还在就不动它——真机上丢第 22 个探针触发重建时，展开的「工具」原样留着。

## 缩略图标的排布规则

按数量选格子：1 个单列（56pt 大图标）、2–4 个两列（40pt）、5–9 个三列（26pt）。永远按实际数量排，不留空格占位——3 个应用摆 2×2 会让右下角空一块，像缺了什么。没有「+N」角标：方块上多一个字就脏了，组里到底有多少个，点开看更清楚。

## 验证

**代码侧**：216 个测试通过（33 个 suite）。本切片新增 14 个：投影（未分组铺成单图标、其余分组各一个方块、「未分类」自己不是方块、分组顺序即展示顺序、0/1/8/9/10/50 个缩略图标、空组照样有方块、隐藏应用不进缩略图、组里只剩隐藏应用时方块在而缩略图空）+ 导航（刚建出来在顶层、展开、back 的两级语义、每次唤起重置、分组没了退回顶层、分组还在不动它）。

**真机侧**（控制台里有 015 整理出的 17 组作为素材）：

- 顶层：22 个未分组单图标铺前 4 行，17 个方块在后——「工具」「开发工具」「效率」各画满 9 个缩略图标，两个应用的组画 2 个，「空组」是空方块（截图 `/tmp/overlay-top-small.png`）
- 展开「工具」：标题 + 32 个应用全在（截图 `/tmp/overlay-group-small.png`）；展开「空组」：空态提示（`/tmp/overlay-empty-small.png`）
- 滚动与重建：往 `~/Applications` 丢 21 个探针 `.app`，内容撑到 9 行；滚到底部（滚动条读 1，文件夹行可见，截图 `/tmp/overlay-scrolled-bottom-small.png`）；再丢第 22 个触发快照重建——子网格仍开着、新探针当场出现在树里、顶层滚动条仍读 1（不跳位）；`setValue` 把滚动条在 0 / 1 之间来回设，网格跟着走，证明读数就是偏移的代理；删光探针后网格恢复原样、无残留
- 不写配置：探针增删全程 `default.json` 的 sha 不变（`721a011c…` 前后一致）
- 最终构建（删掉核对用的环境变量钩子后）启动零窗口、配置不动——静默常驻不受影响

**工具限制**：Esc 与空白点击这两条返回路径没法用可用的自动化工具合成（Esc 按键与屏幕坐标点击都被自动模式拦截；覆盖层窗口的坐标目标被一个 66×20 的辅助窗口顶掉）。这两条由单测（`back()` 的两级语义、Esc 监听器共享同一个返回值）与结构（顶层网格在子网格打开期间从未卸载，辅助功能树里两个滚动区同时可见）保证，人工清单里各留一条。
