# 覆盖层内拖拽整理

**Blocked by**: 007

## 目标

不打开控制台，直接在覆盖层里拖拽整理：调整组内顺序、把应用拖进分组方块、把应用拖出分组、调整分组方块顺序。

## 涉及层

- [ ] 数据层：无新增（复用 `LibraryService` 的移动与排序操作）
- [ ] 逻辑层：拖拽的落点判定（落在图标上 = 排序，落在分组方块上 = 移入）
- [ ] UI层：拖拽手势、拖拽预览、落点高亮、文件夹方块作为放置目标的视觉反馈
- [ ] 测试：落点判定逻辑的单元测试

## 验收标准

- 在分组子网格内拖拽应用，可改变组内顺序，松手后立即持久化
- 在顶层把应用拖到分组方块上，该应用移入该组（方块给出明确的接收反馈）
- 在分组子网格内把应用拖到空白区域，该应用移回「未分类」
- 在顶层拖拽分组方块，可调整分组顺序
- 拖拽到非法落点（如把分组方块拖到另一个分组方块上）时，操作被拒绝且不改变任何数据
- 拖拽过程中按 Esc 取消，不改变任何数据
- 拖拽结果与在控制台中做同样操作的结果一致（同一套 `LibraryService` 操作）
- 拖拽完成后配置立即持久化，重启保持
- 单元测试：落点判定在各种位置组合下的结果

## 备注

- 本切片与 010 的控制台拖拽是两条 UI 路径，但落到同一套领域操作上——这是刻意的，保证两条路径不会产生不一致
- 拖拽到分组方块上时**不做**原版 Launchpad 的"展开动画预览"，只做简单的接收高亮

## 真机验证记录：Esc 取消与「幽灵投递」

**验收项「拖拽过程中按 Esc 取消，不改变任何数据」真机首测失败**（Esc 后数据仍被改）。探针定位（`/tmp/ProbeEsc.swift`，SwiftUI 与 AppKit 两种落点并行对照）结论：

### 现象

- Esc 取消后约 290ms，系统**新起一个瞬时拖拽会话**（AppKit 侧 `draggingSequenceNumber` = 原会话 +1、`updates=0`），把取消时光标下方的落点完整走一遍 enter → prepare → perform（全程 1–6ms），**携带原始载荷**。「幽灵投递」由此得名。
- SwiftUI 的 `dropDestination` 与 AppKit 的 `NSDraggingDestination` 都会收到幽灵；与注入通道（CGEvent / osascript AX 均复现）、窗口层级（level 0 也复现）、松手时机（Esc 后立即松手 / 不松手都复现）无关。
- 触发条件 = **Esc 按下时拖拽在移动中**：光标静止悬停时 Esc 干净取消（exit 立即、无幽灵）。

### 守卫设计

两个信号同时成立才判幽灵，缺一不可（各自的误杀反例都是真机实测出来的）：

1. **落点被瞄准时物理鼠标按钮已抬起**（`NSEvent.pressedMouseButtons == 0`）——真实拖拽的进入必然按着；
2. **自上次离开该落点以来没有任何新的 `leftMouseDown`**（按下代数未推进）——幽灵会话没有起手按下。

单独用信号 1 会误杀「快速擦边」：拖入格子边缘随即松手时，`isTargeted(true)` 回调会迟到到松手之后（buttons 已=0）。单独用「刚失去瞄准」时间窗口会误杀正常落点：正常松手同样走 targeted=false → 1ms → 动作。

### 探针场景矩阵（M9/M10）

| 场景 | 期望 | 实测 |
| --- | --- | --- |
| Esc 移动中取消（tile 落点） | 拒绝幽灵 | ✅ 守卫命中 |
| 正常拖放（tile） | 接收，不误杀 | ✅ |
| 快速擦边进入即松（tile） | 接收 | ✅（信号 2 救回） |
| Esc 移动中取消（容器落点） | 拒绝幽灵 | ✅ |
| 正常拖到空白（容器） | 接收 | ✅ |

工具侧记录：**`Color.clear` 不参与拖拽命中测试**（挂在其上的 dropDestination 全程收不到事件），验证容器落点需换可见视图。

### 落地

- `GhostDropGuard`（AppBoxCore，纯逻辑，5 个单测）由 `guardedDropDestination`（AppBox 通用落点修饰器）接入全部 5 个落点：覆盖层格子、顶层容器（分组方块）、子网格容器（应用回未分类）、控制台分组行、控制台应用行——幽灵落在哪一处，哪一处就改数据，一条路径都不能漏。
- `MousePressCounter` 在应用级装 `leftMouseDown` local monitor，提供按下代数。
- 已知误差窗口（极窄，探针未实测到）：拖拽中光标划出落点又划回、且划回的 enter 回调恰好迟到到松手之后，会被误判为幽灵（该次落点不生效，重拖即可）。判错方向安全：误杀只是不生效，放行才会改数据。
