## 匹配规则：两种形式、三条路径

`AppSearch` 是纯函数。名字有两个「说法」：汉字按字面，拉丁字母按拼音，用哪个由**查询**决定——查询里带非 ASCII 字符就两边都按字面比（把「信」转成 `xin` 反而会撞上「微信」的音节），是纯 ASCII 才把名字转成拼音形式（`.toLatin` 去声调、驼峰补空格、小写、空白压成一个空格）。

命中判定按从紧到松三条路：连写前缀（`weixin`、`visualstudiocode`，汉字转出来是空格分隔的音节，连写后比）、任一整词前缀（`studio`、`catpaw`，词中间不算——`dio` 匹配不上 `studio`）、缩写 + 尾词前缀（`wx` = wei + xin、`vscode` = v·s + code）。前两条是第三条的特例，单列出来更好读也少走弯路。

bundleID 没有「词」可言，只认「某一段的前缀」（`tencent`、`com.tencent` 都行），查询里的点先拿掉——单字母 `a` 不会因为出现在 `com.example` 中间就把所有应用捞出来。`matches` 的三条字段路径：真实名 → 别名 → bundleID。

## 输入即搜索：焦点与按键归属

唤起时控制器喊一声 `model.requestSearchFocus()`（令牌 +1），视图监听它把 `@FocusState` 塞进输入框——「什么时候该有焦点」由按键路径决定，是模型的状态；焦点本身是视图的，两边靠这个数对齐。`onAppear` 里也设一次，兜底首帧。

输入框攥着焦点时（`isFieldEditor == true` 判定），文字与退格**交给输入框自己收**——输入法的组合文字也走它，字符串进来后由绑定整段回写（`replaceQuery`），视图的 `onChange` 负责重算结果。控制器那条路管的是「焦点不在输入框」的兜底：字符直接进模型查询、再把焦点要回来。两条路都汇到 `updateSearch(in:)`，它是幂等的，两边同时触发不会把状态搅乱。

Esc 的语义按层收：搜索中先清查询（回到来时的层级）、子网格里先回顶层、顶层才收起覆盖层——三段都在一处判定。退格在焦点不在输入框时由控制器代收，顺带把按键吃掉，免得系统为此响一声。

## 搜索状态在模型里：可复原、幂等

`OverlayModel` 持有 `query / searchResults / isSearching`，外加一份 `selectionBeforeSearch`：查询从空变非空时把当前高亮记下来、落到第一个结果上；从非空变空（或 `clearSearch`）时层级不动、高亮放回原处。`reset()` 把搜索忘干净——每次唤起都是崭新的。

`tiles(in:)` 是「当前该显示、该导航的格子」的唯一出处：搜索时是结果清单，否则是这一层自己的。视图拿它画格子，控制器拿它算方向键与回车，键盘与画面永远是同一份——和 008 建立的规矩一致。

## 搜索结果层：平铺浮层与空态

`SearchResultsView` 是盖在网格上的整屏毛玻璃层：结果平铺、不分组、按显示名排（隐藏的应用不出现）。空结果显示「没有匹配的应用 / 换个关键词试试；拼音首字母也行，比如 wx 找微信。」而不是空白网格。点空白先清查询（和 Esc 同一条语义）。

- 拼音与别名：`zpqy` → 智谱清言（`t-f.png`）、`wx` → 微信（`t-g.png`）、`catpaw` → CatPawAI（`t-h.png`）、`Fac` → FaceTime（`t-i.png`，大写）

- 方向键 + 回车：`cal` 的结果里 `right` 把高亮挪到 Calendar（`t-j → t-k`），`left` 回来再回车 → Calculator 启动 + 覆盖层收起（键盘路径全程）
- 单击（本切片最后一块拼图）：修复下方那个接线 bug 后，`cal` 结果里用鼠标单击 Calculator → 覆盖层收起（`p8.log` 01:04:44 显隐 → false）+ Calculator 进程起来（pid 54275）；点击前状态 `p8-a.png`
- 核对全程 `default.json` 的 sha 不变（`2094113d…` 前后一致——临时配置就位后，从第一次唤起到最后一次点击收起，sha 与 mtime 都没动过）；核对完把临时配置还原成用户的原件（sha `31d782c2…`），被点起来的 Calculator 已退出

**工具限制**：外部合成按键与坐标点击依旧被自动模式拦截（连 computer-use 的 x/y 坐标点击也拦）。核对用两条替代路径：键盘走**进程内 NSEvent 合成**（应用往自己的事件队列里塞真实 `NSEvent`，监听按正常链路收），鼠标走 **computer-use 的 elementIndex 点击**（AXPress，绕开坐标）。这套 TEMP 代码（`TempVerificationDriver.swift` 与 `AppBoxApp.swift` 里的一行调用）核对完已删除、bundle 重建、全仓 `grep` 无残留。

**真机核对的意外发现：单击图标压根不响应**。搜索与键盘路径全通之后，单击搜索结果毫无反应——没有日志、应用不启动。一度怀疑是合成点击的局限，对照代码排掉后抓到真因：`OverlayController.makeWindow` 首次建窗时给 `OverlayView` 接的是**空闭包**（`onLaunch: { _ in }`、`onDismiss: {}`），而 `apply(_:)` 只在**快照真的变了**时才重接视图——磁盘没动的时候快照恒等，早退分支一进，空闭包就永远留在窗口上。文件夹方块因此独活（`onOpenFolder` 是视图内部直接接 `model` 的，不经过闭包），键盘回车也照常（控制器直接调 `activate(entry)`），两条旁路把 bug 盖住了整整两个切片。

修复：视图装配收敛成唯一一处 `rootView(for:)`，建窗与换快照都从它取，两条路不会再各接各的。修完用同一个实验复验：点击搜索结果 → 收起 + 启动，一次通过。
