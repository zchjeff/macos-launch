# 性能达标验证与调优

**Blocked by**: 014

## 目标

验证 spec 里的三条性能指标并调优到达标：覆盖层唤起 < 150ms、首次全量扫描 < 1s、图标缓存二次启动复用。

## 涉及层

- [ ] 数据层：无
- [ ] 逻辑层：找出并消除冷启动与唤起路径上的阻塞点
- [ ] UI层：无
- [ ] 测试：为可测量的部分（扫描耗时、缓存命中）写基准测试；唤起延迟走手工测量

## 验收标准

- **H1**：图标已缓存时，从按键到覆盖层可见的延迟 < 150ms（本机实测，连续 20 次取中位数）
- **H2**：首次全量扫描 100+ 应用耗时 < 1s
- **H3**：二次启动不重新提取图标——通过比对缓存文件的修改时间或加日志断言
- 覆盖层唤起路径上**不做**同步的文件 IO：图标必须在启动时预加载或异步加载，唤起时只读内存
- 应用启动时（登录后自动启动）不阻塞系统登录完成——冷启动耗时可测量且不造成可见卡顿
- 内存占用有明确数字记录（常态常驻 + 覆盖层打开时的峰值）
- 基准测试能在 CI/本地一键运行，输出可比较的数字

## 验收标准补充

- 若某项指标无法达标，需要记录实际数字、瓶颈位置和已尝试的方案，而不是悄悄放宽指标

## 备注

- 本机为 arm64，图标缓存目录可能达到几十 MB。缓存体积也需要记录，若过大需要说明淘汰策略
- 这一片是收尾验证，不引入新功能。若发现需要结构性改动（如快照模型不适合增量更新），应回到相应切片修正而不是在这里打补丁
