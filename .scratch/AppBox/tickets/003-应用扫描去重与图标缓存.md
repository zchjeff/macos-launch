# 应用扫描、去重与图标缓存

**Blocked by**: 001

## 目标

AppBox 能列出一份准确的应用清单：每个应用有显示名、bundleID、最近已知路径、类别、以及已缓存到磁盘的图标。验证方式是一条调试命令打印清单 + 单元测试。

**这是唯一刻意不含 UI 的切片。** 扫描与去重是最容易出错、最值得单测覆盖的部分，先在一个不牵扯窗口的地方做扎实。验证出口是调试命令，不是界面。

## 涉及层

- [ ] 数据层：`AppRecord` 模型（bundleID 主键、最近已知路径、显示名、类别、图标缓存路径）
- [ ] 逻辑层：`AppScanning` 端口 + FileManager 实现；Info.plist 解析；bundleID 去重与优先级；图标提取与磁盘缓存
- [ ] UI层：无（提供一条调试命令打印扫描结果）
- [ ] 测试：`AppScanning` 的假实现 + fixture，覆盖全部边界

## 验收标准

- 扫描 `/Applications`、`/System/Applications`、`~/Applications` 及其**一级子目录**
- 忽略应用包内部的嵌套 `.app`（如 `X.app/Contents/...`），不把 Helper 当应用
- 解析 `Info.plist` 得到 `CFBundleIdentifier`、`CFBundleName`、`CFBundleDisplayName`、`LSApplicationCategoryType`
- bundleID 缺失时回退用绝对路径作为主键
- 同一 bundleID 出现多个副本时只保留一个，优先级 `/Applications` > `/System/Applications` > `~/Applications`
- 单元测试覆盖：无 bundleID、重复 bundleID、嵌套 `.app`、`Info.plist` 损坏或缺失、`CFBundleName` 缺失时回退用文件名
- 图标提取成功并缓存到 `~/Library/Application Support/AppBox/icons/`，缓存文件按 bundleID + 应用包修改时间失效
- 二次扫描时命中缓存，不重新提取
- 调试命令打印出的清单与访达中实际可见的应用一致，本机约 107 个
- 首次全量扫描耗时 < 1 秒（spec H2）

## 备注

- 图标缓存与配置文件物理分离，保证配置文件始终轻量（ADR-0005）
- 此切片只做"扫描 + 缓存"，不做"与配置合并"，也还没有「失效」概念——那些在 005 / 014 引入
