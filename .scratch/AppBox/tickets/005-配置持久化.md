# 配置持久化：JSON + schema 版本 + 方案文件布局

**Blocked by**: 003

## 目标

配置能落盘并在重启后恢复。文件落在 `~/Library/Application Support/AppBox/`，带 schema 版本号与迁移入口，为后续所有切片提供持久化基座。

## 涉及层

- [ ] 数据层：`AppBoxConfig` 可编码模型（含 `schemaVersion`）；方案文件布局（一方案一 JSON）
- [ ] 逻辑层：读写、原子写入、schema 版本校验与迁移入口、损坏配置的降级处理
- [ ] UI层：无（通过单元测试与调试命令验证）
- [ ] 测试：编解码往返幂等、版本迁移、损坏文件降级、原子写入

## 验收标准

- 配置写入 `~/Library/Application Support/AppBox/` 下的 JSON 文件
- 编码 → 解码 → 再编码结果幂等
- 配置含 `schemaVersion` 字段；遇到低版本配置能迁移到当前版本
- 遇到**高版本**配置（比当前代码新）时拒绝加载并给出明确提示，不静默丢数据
- 遇到损坏的 JSON 时降级为默认配置，且把损坏文件改名备份，不直接覆盖
- 写入是原子的（写临时文件再 rename），进程中途被杀不会留下半截文件
- 图标缓存位于同目录子文件夹 `icons/`，与配置文件物理分离
- 单元测试使用临时目录，不触碰真实的 `~/Library/Application Support/`

## 备注

- `Codable` 在字段变更时会直接解码失败，所以 schema 版本号与迁移入口是必需的，不是可选项（ADR-0005）
- 此切片只做持久化基础设施，具体的配置项（分组、别名、隐藏…）由后续切片逐步填入
