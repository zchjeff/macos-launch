# 全局热键 + 全屏覆盖层窗口

**Blocked by**: 001

## 目标

按 ⌥+Space 唤起一块铺满鼠标所在屏幕、盖住所有窗口的覆盖层，再按一次或按 Esc 收起。网格里填硬编码的假数据。

这个切片的存在意义是**先证伪最高风险的技术点**：原生 macOS 覆盖层的窗口层级、焦点获取、多屏判定。这些没有自动化测试可依赖，一旦做不出来，后面所有领域逻辑都白写。

**状态**：代码完成，核心机制已验证，视觉/多屏/全屏项待人工确认（2026-09-26）

## 涉及层

- [x] 数据层：无（假数据直接写在视图里）
- [x] 逻辑层：覆盖层可见状态、目标屏幕的判定（唤起瞬间读鼠标位置）
- [x] UI层：无边框全屏 `NSWindow`、窗口层级、`collectionBehavior`（跨 Space、覆盖全屏应用）、毛玻璃背景、Esc 与热键收起
- [x] 测试：热键注册与屏幕判定无自动化测试，走手工验证清单

## 验收标准

- [~] 在任意应用处于前台时按 ⌥+Space，覆盖层都能出现在最上层并盖住全屏 —— 热键注册与窗口层级已证（见下），**真实按键未观察到**
- [x] 覆盖层出现后能接收键盘事件（按 Esc 能收起）—— 进程内合成 Esc 经 `sendEvent` 派发，本地监视器收到并收起
- [x] 再按一次 ⌥+Space 能收起 —— `toggle()` 显隐两个方向均已验证
- [~] 鼠标在副屏时唤起，覆盖层出现在**副屏**而非主屏 —— 本机只接了 1 块屏，无法实测；`ScreenSelector` 的选屏逻辑由 9 个单测用"笔记本+外接屏、两屏之间有缝隙"的夹具覆盖
- [ ] 在某个应用的全屏 Space 下唤起，覆盖层仍能正常显示
- [ ] 覆盖层收起后，之前的前台应用恢复焦点
- [ ] 网格中显示硬编码的假应用图标占位（约 20 个），排版不溢出
- [ ] 反复快速唤起/收起 20 次，不出现窗口残留、焦点丢失或崩溃

## 验证方式与证据

`osascript` 合成按键被系统拒绝（`"osascript"不允许发送按键 (1002)`，无辅助功能权限），`screencapture` 也因无录屏权限失败（`could not create image from display`）。因此改用**进程内自检**：临时加一个 `--self-check` 入口，自检完即删除（该入口不在最终代码里）。

经 `open dist/AppBox.app --args --self-check`（即真实的 LaunchServices 启动路径）测得：

| 观测项 | 结果 | 说明 |
|---|---|---|
| `installHotKey` | `true` | |
| 用同一组合再注册一次 | 被系统拒绝 | `eventHotKeyExistsErr`，证明第一次注册**真的落到了系统里**，不是假成功 |
| 换 ⌥+⇧+Space 注册 | 成功 | 排除"注册接口一律返回失败"的假象 |
| `window.frame` | `(0, 0, 1512, 982)` | 等于 `screen.frame`；而 `visibleFrame` 只有 `(0, 62, 1512, 887)`，说明覆盖层**盖住了菜单栏与 Dock 所在区域** |
| `window.level` | `1000` | `screenSaver`，高于 Dock(20) / 菜单栏(24) / 状态栏(25) |
| `isActive` / `isKeyWindow` | 均为 `true` | 覆盖层拿到了焦点 |
| 合成 Esc 后 | `isVisible=false` | |

一个反直觉的坑：**从终端直接跑二进制时 `isActive` 恒为 `false`**（无论是 `.build/debug/AppBox` 还是 `dist/AppBox.app/Contents/MacOS/AppBox`），换成 `open dist/AppBox.app` 走 LaunchServices 就正常。这不是代码问题，是"终端子进程"这种启动方式本身拿不到前台激活。差点据此误判成焦点 bug。

顺带验证了 `NSApp.activate()`（无参、非废弃版本）在真实启动路径上足够用，**不需要** `activate(ignoringOtherApps:)`。

## 待人工确认清单

需要在真机上用眼睛/手确认的部分：

1. 在别的应用前台时按 ⌥+Space，覆盖层是否真的盖住菜单栏和 Dock
2. 覆盖层里的 20 个假图标排版是否不溢出、毛玻璃背景是否正常
3. 在某个全屏应用（如全屏 Safari）里唤起，覆盖层能否正常显示
4. 收起后焦点是否回到原来那个应用
5. 连续快速按 ⌥+Space 20 次，有无窗口残留或崩溃
6. 若有外接屏：把鼠标移到副屏再唤起，覆盖层是否出现在副屏

## 实施中偏离原计划的地方

## 备注

- 全局热键走 Carbon `RegisterEventHotKey`，**不需要**辅助功能权限（ADR-0006）。本切片同时验证了该 ADR 的代价：AppBox 自己不申请权限，但外部脚本也就无法驱动它，所以相关验证只能靠进程内自检或人工。
- 窗口层级需要盖过系统 Dock 与菜单栏；`collectionBehavior` 需要允许加入所有 Space 并覆盖全屏应用
- 应用需从后台转为可接收键盘输入，收起后要把焦点还回去
