# 配置导入导出与多方案管理

**Blocked by**: 010

## 目标

配置能导出为 JSON 文件、能从 JSON 文件导入；能维护多套方案（如「工作模式」「娱乐模式」）并随时切换。

## 涉及层

- [ ] 数据层：方案目录布局（一方案一 JSON + 记录当前生效方案）
- [ ] 逻辑层：导出、导入（含校验与冲突处理）、新建/切换/重命名/删除方案、一键重置
- [ ] UI层：导出/导入的文件选择器、方案列表与切换控件、重置确认
- [ ] 测试：方案增删改切、导入校验、导入冲突处理

## 验收标准

- 能把当前配置导出为 JSON 文件到用户指定位置
- 能从 JSON 文件导入配置
- 导入前校验文件：schema 版本兼容、JSON 结构合法；不合法时给出明确错误并**不修改**当前配置
- 导入时若文件中的 bundleID 在本机不存在，该应用被标记为「失效」而非丢弃
- 导入是原子的：中途失败不留下半配置状态
- 能新建方案、重命名方案、删除方案
- 能切换方案；切换后覆盖层立即反映新方案的分组结构，无需重启
- 同一时刻只有一个方案生效，界面上能清楚看到当前生效的是哪个
- 删除当前生效的方案时，需先切换到另一个方案，或有明确的兜底行为
- 一键重置当前方案：重置为初始状态（仅「未分类」），执行前二次确认
- 方案切换不影响图标缓存（缓存按 bundleID 索引，与方案无关）
- 单元测试：新建/切换/重命名/删除、导出后重新导入的往返一致性、导入非法文件的拒绝、导入含未知 bundleID 的文件

## 备注

- "一个方案一个 JSON 文件"是 ADR-0005 选择 JSON 而非数据库的主要理由之一，本切片是那个决策的兑现
- 方案切换后的生效方案记录需要独立于方案文件本身存储（否则切换时无法知道该读哪个文件）
