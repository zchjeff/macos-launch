# 项目骨架与 .app 打包脚本

**Blocked by**: 无

## 目标

双击 `AppBox.app` 能打开一个空白窗口，且 `swift build` / `swift test` 都能跑通。这是后续所有切片的落地基座。

**状态**：已完成（2026-09-26）

## 涉及层

- [x] 数据层：`Package.swift` 定义三个 target——`AppBoxCore`（library，不依赖 AppKit）、`AppBox`（executable）、`AppBoxCoreTests`
- [x] 逻辑层：`AppBoxCore` 中的 `AppBoxIdentity`（bundle ID / 显示名 / 版本 / Application Support 目录），被 executable 正确引用
- [x] UI层：SwiftUI `App` 入口 + 一个骨架窗口
- [x] 测试：`AppBoxIdentityTests` 两个用例，证明 `swift test` 可用

## 验收标准

- [x] `swift build` 通过，无警告
- [x] `swift test` 全绿（2 个用例）
- [x] `scripts/build-app.sh` 能产出 `AppBox.app`
- [x] 生成的 `Info.plist` 含 `CFBundleIdentifier = com.ethicall.appbox`、`CFBundleName = AppBox`、`CFBundleExecutable = AppBox`、`CFBundlePackageType = APPL`；**不设置** `LSUIElement`（已验证该项不存在）
- [x] 启动 `AppBox.app` 能打开窗口（CoreGraphics 查到屏幕窗口，900×450），Dock 中出现图标（`lsappinfo` 显示 `type="Foreground"`，证明是常规应用而非后台代理）
- [x] 退出应用正常，无残留进程

## 实施中偏离原计划的地方

- **`LSMinimumSystemVersion` 由 26.0 改为 14.0**，`Package.swift` 同步声明 `.macOS(.v14)`。理由：本切片到目前用到的 API 没有任何一个需要 macOS 26，把下限压到 14.0 是严格更优的选择（可移植性更好，成本为零）。原值 26.0 是拆分任务时的猜测，未绑定任何需求。后续若引入 macOS 26 才有的 API，需要同步抬高这个值。
- **测试框架用 Swift Testing 而非 XCTest**，`swift test` 同时输出两套结果（XCTest 0 个 + Swift Testing 2 个），确认工具链支持良好。
